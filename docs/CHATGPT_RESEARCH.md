# ChatGPT educational research queue — v0.5.3c.1 development

The selected ChatGPT account can now run the initial educational AI drafting pipeline after explicit session-only consent in Models ("Allow public exercise AI requests (plan usage)"). This is a narrow development exception to local-only inference, authorized as an optional provider by the author. Local AI remains the default. Sign-in, model catalog, refreshed research guidance, the current automatic or manual choice, account scope, and two remaining daily attempts must all be available. No paid API fallback or new purchase is implemented. The authorized plan may consume subscription allowances or credits; the app's attempt count is not a monetary cap. Consent defaults off on process restart, is cleared on sign-in/sign-out or switching to Local AI, and may be disabled at any time. No patient data, conversation, notes, source HTML, sample sequences, user search text or arbitrary prompts are sent. The native bridge accepts only five predefined educational task identifiers and ten supported language codes. A second request includes the bounded first AI response for critique; it is not independent validation. Neither request has external tools. No clinical or general web research is enabled.

The queue still requires reviewed local documentary evidence. It processes the five curated Rosalind records only in this provider mode (automatic or manual). It sends a fixed authored description of the abstract task, not the downloaded statement or dataset. It saves a separate ChatGptResearchDrafts record with provider and model slug, not a fabricated weight hash. The source hash identifies the local evidence snapshot, not content supplied to the remote model. Existing local drafts are unchanged. The report viewer and PDF/ZIP use the selected provider's draft directory. Reports remain explicitly unvalidated. Original challenge data and terms remain separate.

Both requests use the existing serialized OAuth worker, the authorized model slug and official /v1/responses with store=false and stream=true. The provider's data handling terms still apply. The daily counter reserves one attempt per request before dispatch. Partial, failed, refused, oversized or interrupted output is rejected; response.completed is required. Usage/transport failures pause the queue after a failed draft, while missing readiness prevents new jobs. Resume is explicit. Cancellation discards results and stops later dispatch, but cannot undo a request already delivered; network read/write and refresh are cooperative, not hard end-to-end deadlines. No automatic retry or fallback. The 12-job session ceiling still applies. Manual model selection remains session-only; a missing or changed model blocks reuse, and prior draft records are not overwritten. The research gate for validated scientific execution remains false. General scientific statements, rights and datasets, experiments, translation, conversation integration and clinical/community functionality are pending.

## Validation

This is source only, not a release. Compile Java and C# in Unity; audit the existing OAuth and native dependencies, test account authorization, consent and revocation, model choice, quotas, SSE completion/refusal, cancellation, provider switching, reports, and device language/layout. No live account or inference call, no build or Quest 3 test was performed. No new dependency, credential or media is distributed.
