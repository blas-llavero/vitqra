# Synthetic telepresence — v0.7.1 initial

Closed local pose exercise. No actual tracking, camera, microphone, audio, video, network, recording, persistence, media assets or patient information. Uses fictional PrivateRoomA/B Care/Join grants through VitqraAvatarMeeting. Joining does not confer record access. PatientA and ClinicianA and their B counterparts are existing fictional enum constants, not actual people or device identifiers. The preview is an editor-only 2D projection of fictional 3D points, not a live hologram. No normal workspace, geometry or saved layout changes. No new dependency.

Head and hands sharing default off. Each channel has separate consent. A change clears the snapshot; samples captured before the latest consent change are rejected. Leave, clear and grant expiry remove state; rejoining starts with consent off. Only another joined authorized viewer can read the latest frame. No movement history. Seven fixed samples include neutral, head turn, hand gestures, head/hand loss and invalid coordinates. Disabled channels are omitted before storing the frame. Missing tracking hides the affected points. Fictional bounds: x/z ±2000 mm, y 0–2500 mm, yaw ±180 degrees. Reject stale samples (500 ms or older), future captures, non-increasing sequence numbers and decreasing capture times. Invalid retained coordinates clear the frame. These are synthetic bounds, not physical safety limits. The clock advances manually (0–60000 ms); no real timing, interpolation, coordinate alignment, body tracking or live synchronization. Sequence resets at new membership; production transport needs authenticated per-session epochs and replay defense. Previously returned immutable objects cannot be remotely erased; only current internal state is cleared.

Editor menus: VITQRA > Synthetic Telepresence Preview / Run Synthetic Telepresence Checks. Join both fictional participants, opt in to channels, submit a predefined sample and select the other viewer. Advance 500 ms to hide it. Core supports both rooms; preview uses A. Labels in ten device languages, invariant technical result codes. JavaScript reference reproduction passed 33 assertions; C# supplied but not compiled or run. Shared fixture design, not a real security audit. No live or clinical use authorized.

Future: explicitly authorized OpenXR tracking, separately scoped media and motion consent, no raw room meshes, absolute home coordinates, biometrics or clinical content by default. Movement may identify people. Require authenticated membership, consent enforcement on server and receiver, authenticated encrypted transport, scoped epochs, bounds/rate limits, revocation and independent privacy/security review. No recording by default; provide accessible alternatives and visible capture indicators. Test reference frames, tracking loss, latency and motion discomfort before deployment.
