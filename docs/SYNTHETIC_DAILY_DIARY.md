# Fictional daily check-in, reminders and device authorization — v0.6.2b

Author-requested six one-touch responses: no symptoms today, better, same, worse, unsure, unable to take the measurement. Interactive Unity editor demonstration, not actual patient intake. No free text, real sensor connection, clinical data, persistence, server, upload, notifications outside the editor or AI. Do not enter real patient information. Session entries disappear on closing/reload; the explicit new-session button clears the fictional session. Two fixed sample schedules (daily and alternate days, 30-day window) illustrate future clinician-approved condition-specific protocols; neither is a medical recommendation.

## Semantics and coverage

NoSymptoms is an explicit qualitative self-report, not a numerical measurement. Better/Same/Worse are subjective comparisons with the prior day (future production forms must explain the reference interval); no numerical conversion or inferred severity. Unsure and UnableToMeasure are answered slots but not known clinical states. Unanswered is a separate count. Scheduled vs extra responses are separate; one of each per fictional day; no silent overwrite or retroactive editing. Future correction workflow must retain original/version and reason. Device readings never replace subjective answers. Distinct expected, answered, known state, unknown, unable, unanswered, extra and device counts. No forced class ratio, imputation or prevalence adjustment. The earlier numerical fixture remains separate; this module is not wired into the real dataset quality or research engine. Passing any coverage condition does not authorize research.

## Voluntary reminders and device consent

Both opt-ins default off. Reminder checks use fictional local time, once per scheduled day after selected time, never for already answered scheduled slots. No catch-up, no forced response, no clinical or emergency alerts. The editor button simulates a reminder; no background OS notification or actual real-world schedule. Real deployment needs approved protocol, time zone/DST handling, quiet hours, opt-out and device notification permission; use neutral lock-screen text, no diagnosis disclosure. Device authorization permits a single fixed unitless demo measurement per day; revoke prevents new imports, previous entries remain. The device source is explicitly simulated, not a health API or connected wearable. Real device ingestion must verify identity, scopes, origin, timestamps/units, quality, duplicates, lawful basis, revocation, deletion and permissions; no real connector or vendor dependency selected. A future adapter must preserve original raw measurement and provenance and never automatically infer symptom status from it.

All writes require the fictional owner and v0.6.0 Care/AddOwnObservation; reads require current Care/Read. This is client-side simulation, not real authentication. No patient data may reach GitHub, ordinary reports, research AI or public rooms. Real data and clinical release remain blocked. Menus: VITQRA > Synthetic Daily Diary Preview / Run Synthetic Daily Diary Checks. Ten localized labels; technical enum/status identifiers remain English. No runtime XR, Android app or APK. JavaScript reference checks executed: 79. C# tests supplied, not compiled/executed in Unity. No actual security/clinical validation.
