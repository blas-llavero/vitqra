# Ephemeral digital trust — v0.6.4

Source-only replacement design after an opaque-content warning on the previous proposal. No static certificates, signatures, encoded payloads, key material or personal data in this milestone. The previous proposed public test vector is not included. All code is readable text. No network or runtime XR change.

Editor-only closed exercise constructs the v0.6.3 fictional corrected revision and favorable unsigned Domain draft, binds resource, exact revision digest, reviewer, verdict, rationale, day and synthetic scope, and generates an ephemeral RSA-2048 key and self-signed X.509 certificate using platform cryptographic APIs. RSA PKCS#1 v1.5 with SHA-256. Only public DER and detached signature remain in the in-memory fixture object after disposal of signing objects. No explicit key serialization or file writing; platform provider storage behavior and reliable key-memory erasure have not been independently verified. Do not use this code for real signing. No key or certificate export API. The verifier pins the generated public certificate within its own session, checks the detached signature and fictional revision scope, and fails on changed document, signature or certificate. A fresh fixture is not a verified identity or trusted issuer. No external trust chain, OS trust import, signing of arbitrary documents, real certificate acceptance or actual clinical release.

Fixture dates: day 25 signing, revocation effective day 60, expiry day 90. Unknown simulated revocation status fails closed. No trusted timestamp, CRL, OCSP or real time validation. Fictional dates and status are not real revocation evidence. The editor preview has ten translated labels and English technical enum codes. Actual scientific approval, clinical release and real certificate trust remain false.

Independent Python reference using installed open-source cryptography (46.0.4 in test environment) executed 12 cases and verified a self-signature, with distinct generated certificates. It exercises an analogous simpler payload, not Unity C# or exact C# revision binding. Results contain counts only. Unity test supplied but not compiled/executed; CertificateRequest and RSA/X509 support must be tested on the target Unity Editor platform, and unsupported implementations must not be used. No new runtime dependency. Python package is a test-only prerequisite. Menus VITQRA > Ephemeral Digital Trust Preview / Run Ephemeral Digital Trust Checks.

Future: verified identity and authority, reviewed signature format, institutional trust anchors, trusted timestamps, real revocation, scoped external certificate verification and independently audited private-key management. Never equate cryptographic integrity with scientific or clinical validity. The actual v0.6.3 review center and package remain unchanged. No certification or authorization to deploy.
