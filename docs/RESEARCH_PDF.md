# PDF and research archive — v0.5.3 development

After documentary reporting and optional two-pass local AI drafting, the automatic/manual queue attempts to create a local PDF and ZIP before advancing. The main directory design, paging and research controls are unchanged. The existing detail reader includes View PDF; from the optional graphical browser, use View report or the text reader first. Only PDFs generated by this feature are opened; downloaded notice PDFs remain separate. Existing HTML/TXT reports stay available on non-Android platforms.

The PDF uses Android PdfDocument and StaticLayout for paginated A4 text, with system font fallback, wrapping, a repeated research-only warning, page numbers and a VITQRA heading. The actual device language rendering (particularly RTL and Indic/CJK fonts), text extraction, font embedding and visual layout must be tested. No PDF generation is claimed for the Unity Editor. Java source plugin requires Android API 23 or newer and Gradle; import the Java file under Assets/VITQRA/Android and select Android only in its plugin settings. Keep com.blasllavero.vitqra.pdf.VitqraPdf and public static methods when enabling Android code shrinking. No new third-party package, native binary or paid API is introduced. Android/Unity platform dependencies remain as before.

An archive contains report.txt, report.html, report.pdf and manifest.txt. The text/HTML/PDF incorporate the documentary report and, when available, distinctly labeled AI alternatives and human-impact critique with source/model identifiers. The report remains unvalidated and does not establish a competition win, safety or clinical efficacy. Source documents and datasets stay in existing private evidence storage rather than being duplicated in ZIP; the report inventories them with source URLs and hashes. No full statement or general experiment is added. ZIP is not yet a complete reproducible data bundle; no public sharing or submission is enabled.

The app stores packages under Application.persistentDataPath/VITQRA/ResearchPackages/<content SHA-256>/, with separate revisions when the report or draft changes. It checks the existing documentary report, reconstructs content, checks file and ZIP bytes against the manifest, checks PDF signature, page count and first-page rendering before accepting a new package. Existing invalid packages are not overwritten. ZIP entries are fixed names, never extracted. For viewing, verified PDF bytes are copied to a short-lived private file and passed to Android PdfRenderer; the page is returned as PNG and displayed in the existing panel. PDF work runs in a serialized worker; cancellation is cooperative, and a platform call already running may finish before the result is discarded. Closing or changing views cancels viewing; stale revisions cannot update the panel. The reader does not accept arbitrary paths, URI schemes, remote PDFs or attachments. The manifest is not signed, so coordinated local tampering is not ruled out. No data is encrypted by this module; no patient data should be stored.

Limits: 48 pages, 8 MiB PDF, 10 MiB ZIP, 32 MiB package store, 40,000 UTF-16 body characters. Temporary files and staged writes can temporarily exceed final storage quota; failed operations try to clean up. No new permissions. User-facing export, deletion, arbitrary PDF viewing, richer scientific figures, PDF accessibility and complete evidence archives remain pending. Original source rights and AI validation requirements are unchanged. The existing 12-job ceiling remains.

Validation: compile Java and C# in Unity Android build, test all ten languages and PDF page navigation, actual file and ZIP integrity, interrupted generation, low storage, malformed local packages, background/foreground changes, UI memory and performance on Quest 3. No Unity/Android compilation or headset test was performed in this source milestone.
